# Experiment protocol

## Research question

How do TF-IDF cosine similarity and BM25 compare in retrieving annotated evidence sentences from cited reference articles, and how does retrieval vary with lexical overlap between a citation context and candidate evidence sentences?

## Dataset

Use the public Citation-Integrity corpus in MultiVerS format from <https://github.com/ScienceNLP-Lab/Citation-Integrity>. Acquire the four JSONL files with `python scripts/download_data.py`. That script verifies their Git blob IDs against `results/data_audit.json`. Do not include raw dataset files in this repository.

## Task construction

For each citation claim:
- Query: the claim text in the citation context.
- Candidate pool: all abstract sentences from documents listed in `cited_doc_ids`.
- Gold item: each `(document_id, sentence_index)` pair listed in `evidence`.
- Claims without sentence-level gold evidence are excluded from Recall@k and MRR@10 aggregation and are counted separately by the audit.

## Methods

1. TF-IDF cosine similarity: lowercase alphanumeric tokenization, word unigrams, sublinear term frequency, smoothed inverse document frequency, L2 normalization, and cosine ranking.
2. BM25: same lowercase tokenization and candidate pool, with `k1=1.5` and `b=0.75`.

Both rankers return the top 10 candidates for each query. The code implementation is the authoritative definition of tokenization and scoring.

## Metrics

- Recall@5 and Recall@10: fraction of sentence-level gold items retrieved in the top k, divided by the number of gold items.
- MRR@10: reciprocal rank of the first gold item in the top 10; zero if no gold item occurs in the top 10.
- All headline metrics are macro-averaged over claims with at least one sentence-level gold item.

## Paired comparison and deeper analysis

The paired bootstrap resamples test claims with replacement 4,000 times using seed 13. It computes the TF-IDF minus BM25 mean metric difference and percentile 95% intervals. Lexical overlap is the maximum fraction of unique query tokens shared with any candidate sentence. The overlap quartile cutoffs are calculated on development claims and applied unchanged to test claims. This subgroup analysis is descriptive, not causal.

## Execution order and leakage controls

1. Download and audit the dataset.
2. Run the development split and inspect representative predictions.
3. Freeze source code and `configs/protocol.json`.
4. Run the test split once after the freeze.
5. Run aggregate evaluation and paired bootstrap.
6. Record the Git commit, environment, command output, and deviations.

Do not tune model parameters on the test split. Do not change the data split after viewing test metrics without documenting the deviation and treating the result as exploratory.
